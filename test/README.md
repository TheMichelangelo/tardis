# Перевірки тексту та UTF-8

Запуск усіх тестів:

```bash
flutter test
```

Лише нові перевірки тексту:

```bash
flutter test test/unicode_content_test.dart test/unicode_rendering_test.dart
```

`unicode_content_test.dart` автоматично знаходить усі JSON-матеріали в
`src/data` (крім облікових записів), суворо декодує UTF-8 та перевіряє вкладені
рядки на символ заміни, небажані керівні символи й типові ознаки пошкодженого
кодування. Порівнює байти з відповідними файлами `public/src/data` та текст,
прочитаний завантажувачами матеріалів.

Для кожного класу й мови перевіряється повне збереження каталогу та повторне
читання через `LessonRepository` і `JsonLessonStorage`. Окремий приклад містить
український алфавіт, різні апострофи, переноси рядків, нерозривний пробіл,
символи з комбінованими діакритичними знаками та емодзі. Перевіряються також
перезапис, відновлення сесії, розділення даних за класом і мовою та відкриття
збереженого уроку за кодом. `shared_preferences` використовує стандартну
тестову реалізацію; це не інтеграційний тест SQLite чи сховища браузера.
Нативний кеш читає справжні UTF-8-файли з окремої тимчасової папки, яку тест
видаляє після завершення; некоректні байти мають спричинити помилку.

`unicode_rendering_test.dart` перевіряє точний текст після збереження,
відображення розв'язку вчителю, введення української відповіді та відсутність
обрізання тексту. Чотири PNG у `test/goldens` доступні для opt-in перевірки:

- вправу учня на телефоні;
- вправу вчителя з відкритим розв'язком на широкому екрані;
- ту саму вправу на телефоні з масштабом тексту 1,7;
- введення коду на екрані шириною 320 із масштабом тексту 1,7.

Тести завантажують наявні в проєкті Noto Sans Regular/Bold та Material Icons,
фіксують платформу оформлення Android, розмір поверхні й щільність пікселів.
Порівняння PNG точне, без порогу допустимих відмінностей, але вимкнене за
замовчуванням у CI. Растери шрифтів і Material UI відрізняються між macOS та
Ubuntu, тому обов'язкові CI-перевірки використовують семантичний текст,
Unicode code points, розмітку та межі RenderParagraph. Для локального запуску
golden-перевірок у середовищі, де створені PNG, використайте
`--dart-define=RUN_UNICODE_GOLDENS=true`.

Воно не перевіряє
системні шрифти кожного пристрою чи вигляд експортованого PDF.

Якщо вигляд інтерфейсу навмисно змінено, оновіть еталони:

```bash
flutter test --dart-define=RUN_UNICODE_GOLDENS=true --update-goldens test/unicode_rendering_test.dart
flutter test --dart-define=RUN_UNICODE_GOLDENS=true test/unicode_rendering_test.dart
```

Перегляньте кожен змінений PNG перед додаванням у коміт. Не оновлюйте
еталони автоматично в CI: відмінність може виявитися помилкою. Різні версії
Flutter/рушія можуть змінювати растеризацію; при такому збої спочатку
звірте середовище тестування. Файли порівняння при невдалому тесті з'являються
в `test/failures` і не додаються до Git. Наявні workflow запускають ці
перевірки разом з рештою тестів командою `flutter test`.
